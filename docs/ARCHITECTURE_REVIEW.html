Code quality and repo hygiene

Not refactors, but best-practice fixes. All eight are resolved; the outcome follows each item.

  • H1 · Two dependency lists that disagree. jinja2 is only in requirements.txt, which also installs pytest, pytest-cov, pytest-mock, mypy, pylint and black into the production image. Make pyproject.toml the single source (runtime deps plus a dev extra) and generate a hashed lock (uv lock or pip-compile --generate-hashes). Closes REVIEW.md P2 #4. Resolved: uv.lock pins 100 packages; requirements.txt is its hashed runtime export, installed with --require-hashes; CI and pre-commit fail if either drifts.
  • H2 · Python version claim. requires-python = ">=3.8", Black targets py38–py312 and mypy python_version = "3.8", but 15 modules use runtime list[...]/tuple[...]/dict[...] without the __future__ import and the image is 3.11. Set >=3.11 in all three places; drop typing.List/Dict over time (Ruff UP006 does it mechanically). Resolved: requires-python = ">=3.11", Ruff py311, mypy 3.11; Ruff UP rules modernized the annotations in one commit listed in .git-blame-ignore-revs.
  • H3 · Two pytest configs. pytest.ini silently overrides [tool.pytest.ini_options] (the unit marker exists only in the ignored one). Keep the pyproject.toml section and delete pytest.ini. Resolved in PR #19.
  • H4 · Lint stack. There is no .pre-commit-config.yaml and no CI (REVIEW.md P2 #1). Replace black, isort, flake8 and pylint with Ruff (format and lint), and run it in a new pre-commit config and in the CI gate. Extend check_logging_style.py: 113 single-line f-string log calls and 48 stdlib extra={…} calls sit beside structlog key/value calls. Resolved: Ruff replaces black, isort, flake8 and pylint; .pre-commit-config.yaml and .github/workflows/ci.yml run lint, format, lock, logging, catalog and test checks. The logging check also rejects f-strings and extra=, and it now scans the repository (it had been scanning scripts/src and passing on nothing).
  • H5 · Swallowed errors. Many except Exception handlers just return 0/None, pass or continue (37 at review, mostly selenium_utils, driver.py, base_storage.py). AGENTS.md forbids this. Enable Ruff BLE001/S110/S112 and mark the deliberate ones with # noqa: BLE001 — reason, so the count can only go down. Resolved: 132 handlers were fixed: tracebacks kept, exceptions narrowed (OSError, WebDriverException, archive read errors), or justified with # noqa: BLE001 - reason. Ruff also found a missing datetime import that broke every Oddspedia resolve run.
  • H6 · Tracked generated file. preprocessed_configs/config.xml is generated by ClickHouse ("Do not edit it"). git rm --cached it and add preprocessed_configs/ to .gitignore. Resolved in PR #19.

1. Fail-closed Bronze table admission

Done ADR 0031, 0032 · PR #17

Was: insert_dataframe_with_dlq wrote the DLQ and re-raised, but its callers caught Exception and returned 0 rows, so the run exited 0 and Silver and Gold published the scope without that table.
