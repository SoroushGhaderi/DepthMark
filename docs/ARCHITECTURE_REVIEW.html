Problem (was): the shape of each Bronze table was defined in four places (processor keys, a hard-coded rename map, live DESCRIBE coercion, and the layer contract). The coercion clipped, rounded, and filled values, and every failure path ended in return 0.

What changed: the setup DDL is now the only table definition. The processor emits DDL column names (model fields renamed: event_time, score_at_event, shot_id, minute, minute_added, coach_id). admit_rows checks every value of a date before any insert. The loader checks once per run that every Bronze table exists and matches its DDL. Failures are classified (ADR 0031). A Date-Level Failure (unreadable payload, processor error, rejected row, inadmissible value, conflicting identity) fails only its date: nothing is written for it, the run continues, and the result lists every failed date with a message naming the file, match, table, column, and rule. A Run-Level Failure (drifted table, failed insert, held write lock) stops the run. Either exits non-zero.

  • Locality: a column change touches the processor and the DDL only. The rename map, INT64_COLUMNS, UNIQUE_KEY_COLUMNS, the cards_only/lineup_data special cases, and assert_bronze_dataframe_contract are gone.
  • Leverage: closes the open "Bronze admission fail-closed" item in REVIEW.md. The processor no longer swallows section errors, and a match without a date is rejected instead of being stored as 1970-01-01. Three source quirks are resolved explicitly in the processor: fractional possession is rounded half to even, different events sharing an id get distinct deterministic ids, and a repeated lineup player keeps the first entry.
  • Tests: 71 new tests (admission rules, warehouse-schema check, the source-quirk rules, both failure classes, replace, removal, rebuild, and the write lock against an in-memory fake warehouse, and a processor ↔ DDL contract test on a synthetic payload fixture). Full suite: 403 tests.
  • Verified on real data: three real dates loaded through the new path into scratch tables matched the existing bronze.* rows exactly in all 15 tables (about 130k rows).
Clearing and reloading data (ADR 0032). The old --truncate emptied every table whatever the scope, before loading, so a failure left Bronze empty. Bronze data operations are now scoped by Source Date (the Historical folder name): load-fotmob-bronze --replace admits a date before removing and reinserting its matches; remove-fotmob-bronze deletes a date, range, or month (full history truncates) and prints the Silver and Gold commands for the stale Match Dates; --full-history --rebuild is truncate-and-reload without the empty window: it loads staging copies and swaps them in only if every date loaded. One non-blocking write lock keeps Bronze writers from interleaving. --truncate is deprecated.
Full-history check. The new read → process → admit path ran over every stored payload: 4,719 dates and 661,837 matches. No file was unreadable, no processor section failed, and no value needed clipping, rounding, or filling. The strict rules first failed 443 dates. Each was a place where the old loader had been silently losing data: 663 cards and 52 goals that shared an id with a different event, 29 repeated lineup entries, and 169 period rows dropped for fractional possession. The processor now gives colliding events distinct deterministic ids, keeps the first lineup entry, and rounds possession half to even. All 4,719 dates admit (35.9M rows). Reloading Bronze restores the lost rows.

Problem (was): three modules parsed the same frontmatter differently. The quality gate skipped malformed catalogs with continue, removing them from duplicate checks. The 93 sig_match_* catalogs said entity: team, so ClickHouse activations recorded match while MongoDB recorded team. The Gold runner found SQL by glob, so status decided nothing, and every MongoDB document embedded the generic runner's source.

What changed: one module is the only catalog reader, and one invalid catalog fails every consumer before it writes. entity is the subject scope and equals the id segment; status is active or deprecated and now decides what runs. asset_paths.runner is gone. The MongoDB sync mirrors the catalog: it replaces changed documents whole, skips unchanged ones by content hash, and prunes orphans behind a mass-deletion guard. The index table is generated by check_signal_catalogs.py --write-index. Catalogs and contracts moved out of scripts/, and the contracts were rewritten by artifact, with each rule naming the check that enforces it.

  • Correction to this review: the proposed row_identity ↔ DDL ORDER BY check would have failed 132 signals without a defect, because ORDER BY is a sort key. The enforced contract is the identity chain: row_identity columns exist, the DDL signal_instance_id default hashes them in catalog order, and ORDER BY ends with signal_instance_id. All 344 signals satisfy it.
  • Verified: generated activation SQL is byte-identical for all 344 signals; Gold job lists are unchanged for every documented selector; every MongoDB document validates against schemas/mongodb/signals.schema.json.
  • Tests: 59 new tests (465 in total) across the loader, the check command, job selection, the activation builder, the quality gate, and the sync.
  • Follow-up: all 344 signal DML files still insert into the legacy gold.sig_* name, which the runner rewrites; migrate them to gold_signals.*.

Problem: the canonical entry points are shims that import from the deprecated files, which hold the real code. That code (date expansion, identity checks, catalog SQL generation in the 606-line activation builder, setup helpers) can only be reached with path tricks.

Solution: each command gets main(argv) -> int in a src/ module. Canonical and legacy scripts become shims around it. depthmark calls it in-process. The editable install replaces every sys.path.insert.

  • Locality: each command's logic lives in one importable file. 20+ Oddspedia compatibility adapters can share one deprecation helper with a stated removal version.
  • Tests: tests import modules normally, and mypy and coverage see the code. Right now --cov=src leaves out most script logic, which is part of the 52% figure.
ADR 0002 / 0010: ADR 0002 keeps subprocesses as the boundary for orchestrating layers. That can stay for run_fotmob_pipeline, where process isolation helps. The depthmark → script hop is only an extra process. ADR 0010 already points to src/ services; this finishes that move.

Code quality and repo hygiene

Not refactors, but best-practice fixes.

  • Two dependency lists that disagree. jinja2 is only in requirements.txt. requirements.txt also installs pytest, mypy, pylint and black into the production image. Make pyproject.toml the single source and generate a hashed lock (uv lock or pip-compile). This also closes REVIEW P2 #4.
  • Python version claim. requires-python = ">=3.8", but 16 modules use runtime list[...]/tuple[...] without the __future__ import, and the image is 3.11. Set >=3.11, align Black/mypy targets, and drop the typing.List/Dict style over time.
  • Two pytest configs. pytest.ini overrides [tool.pytest.ini_options] without warning (the unit marker exists only in the ignored one). Keep one.
  • Lint stack. Replace black, isort, flake8 and pylint with Ruff (format and lint) in pre-commit and CI. Extend check_logging_style.py: there are 131 f-string log calls and 84 stdlib extra={} calls beside structlog key/value calls.
  • Swallowed errors. 37 except Exception handlers just return 0/None, pass or continue (mostly selenium_utils, driver.py, base_storage.py). AGENTS.md forbids this. Add Ruff BLE001/S110 and allow-list the deliberate ones.
  • Tracked generated file. preprocessed_configs/config.xml is generated by ClickHouse ("Do not edit it"). Untrack it and add it to .gitignore.
  • Coverage scope. --cov=src leaves out scripts/, where much of the logic lives. Candidate 3 fixes this structurally. After that, add fail_under.
  • Compatibility adapters. About 20 deprecated scripts and 20 CLI aliases have no removal date. State one in ADR 0024 (for example "removed in 3.0") so the count shrinks.
