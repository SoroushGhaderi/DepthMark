Problem: the odds rules moved to odds_contract.py, but the event-identity and score rules (_same_team_pair, _event_identity_mismatch_reasons, _parse_football_score_payload, _football_score_from_meta) still sit beside DOM driving and can only be reached through private names. scrape_match is one 543-line body, and 785 lines of the module are JavaScript held as Python strings.

Solution: move the identity and score rules into a pure module next to odds_contract.py and test them with recorded fixtures. Break scrape_match into named steps (load, verify identity, collect odds, score, stats). Optionally move the JavaScript into .js files loaded once. match_collector._navigate_to_date gets the same treatment.

REVIEW.md P3 #9 says to split only when the next Oddspedia change touches these files. That still holds: this is not worth a change of its own.

A2. Query-id tagging and retry in warehouse_session

Open Worth exploring Remote but owned

src/warehouse/identities.py (warehouse_session, warehouse_client), src/integrations/clickhouse/client.py

Problem: every warehouse connection now goes through warehouse_session(), but queries carry no shared query id and transient failures are not retried. A failed scope cannot be traced across system.query_log, and a dropped connection fails the whole stage.

Solution: have the session set a query-id prefix from the run (command, scope, identity) and apply one bounded retry policy for connection errors only, never for inserts that may have landed. The session is now the single place to add both.

This is the open half of REVIEW.md P3 #8; subprocess timeouts and process-group cancellation are done.

Accepted exceptions

Deliberate and not planned for change. Listed so the re-verify counts below are not read as regressions.

  • Raw ClickHouse health probe. src/operations/health.py calls clickhouse_connect.get_client directly, and ClickHouseClient.health_check() delegates to it. A probe must work before identities and settings are trusted.
  • OS and terminal environment reads. NO_COLOR and FORCE_COLOR in src/common/logging.py, and PROGRAMFILES/PROGRAMFILES(X86) in src/oddspedia/scraping/driver.py, are platform conventions, not DepthMark configuration, so they stay outside Settings.
